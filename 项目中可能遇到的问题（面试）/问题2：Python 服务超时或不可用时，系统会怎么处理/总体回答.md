## Python 服务超时或不可用时的处理机制
### 1. 超时配置
在 PythonClientProperties.java 和 OrchestratorProperties.java 中配置了超时参数：

- 连接超时 ： connectTimeoutMs = 3000ms （默认）
- 同步调用超时 ： orchProps.syncTimeoutMs()
- 异步调用超时 ： orchProps.asyncTimeoutMs()
### 2. 客户端层面的处理 (PythonComputeClient.java:132-167)
```
private ReviewSyncResponse compute(ReviewSyncRequest 
request, long timeoutMs) {
    try {
        return client.post()
                .uri(pyProps.getSyncPath())
                // ...
                .timeout(Duration.ofMillis
                (timeoutMs))  // 设置超时
                .block(Duration.ofMillis(timeoutMs + 
                1000));
    } catch (Exception e) {
        // 识别超时异常
        if (msg.contains("timeout") || msg.contains
        ("Timeout")) {
            throw new PythonTimeoutException("Python 
            compute timed out after " + timeoutMs + 
            "ms", e);
        }
        throw new PythonServiceException("Failed to call 
        Python service", e);
    }
}
```
### 3. 服务层面的处理 (AbstractReviewExecutionStrategy.java:48-89)
使用 模板方法模式 封装 Python 调用的完整生命周期：

- 成功路径 ：调用 Python → 记录结果 → 更新状态为 SUCCESS/HUMAN_REVIEW
- 失败处理 ( handlePythonFailure 方法)：
  - 记录失败指标
  - 将任务状态设置为 FAILED
  - 保存错误码和错误消息到数据库
  - 记录审计日志
### 4. 异步任务的特殊处理 (AsyncStrategy.java:144-164)
### 5. 重试机制
- Kafka 重试 ：消息队列支持自动重试
- 最大重试次数 ： MAX_RETRY_COUNT = 3 ( AsyncStrategy.java:50 )
- 手动重试 ：通过 retryStuckTask 方法支持人工触发重试
### 6. 健康检查
项目包含 PythonHealthIndicator.java ，用于监控 Python 服务的健康状态。

## 总结
当 Python 服务超时或不可用时，系统会：

1. ✅ 检测超时并抛出专用异常
2. ✅ 将任务状态标记为 FAILED
3. ✅ 记录详细的错误信息
4. ✅ 支持自动和手动重试（最多3次）
5. ✅ 异步任务超时会主动取消，避免资源泄漏
6. ✅ 提供健康检查端点监控服务状态

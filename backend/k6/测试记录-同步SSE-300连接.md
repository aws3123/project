# 同步 SSE 流式审核与断线重连测试记录

## 1 测试概况

| 项目 | 内容 |
|---|---|
| 测试类型 | 同步审核 SSE、断线重连与事件补齐 |
| 测试标识 | `sse-sync-202609170320` |
| 接口 | `POST /api/review/sync/stream` |
| 重连接口 | `GET /api/review/tasks/{taskId}/stream` |
| 总连接数 | 300 |
| 模拟断线数 | 30（10%） |
| 断线策略 | 收到首个带事件 ID 的事件后主动断开 |
| 重连方式 | 携带 `Last-Event-ID` |
| LLM模式 | mock，`LLM_MOCK_DELAY_SECONDS=2` |
| RAG模式 | 本地离线 RAG，`HF_HUB_OFFLINE=1`、`TRANSFORMERS_OFFLINE=1` |

## 2 测试目标与链路

本轮验证同步流式审核接口能否持续转发审核过程事件，并验证客户端断线后通过 `Last-Event-ID` 从 Redis 事件缓存重放缺失事件，最终收到完整终态事件。

```text
客户端 → Java ReviewController → SyncStrategy
      → Python Agent/RAG/LLM 流式处理
      → Java SseEmitter → 客户端

断线后：客户端 → Java StreamResumeService
      → Redis 事件缓存重放 → 继续尾随 → run_finished
```

本轮不经过 Kafka、Outbox、Python Kafka Consumer 或异步回调 Consumer。

## 7 结论与限制

本轮同步 SSE 测试通过。300 条同步流式连接中，按计划断开30条，全部使用 `Last-Event-ID` 成功重连并收到终态事件，终态补齐率达到100%。

该结果只代表同步 SSE、Java 到 Python 的流式转发和 Redis 事件重放能力，不代表 Kafka 异步链路的吞吐、消费者故障恢复或 Broker 容灾能力。
